# User manual (取説)

The manual for members, with screenshots taken automatically from the real app screens.

```
manual/
  pages/<name>.md        the manual's text (Markdown, Japanese, written for non-engineers)
  images/<scene-id>.png  screenshots, generated by `pnpm manual:shoot` and committed
```

- A page refers to a picture as `![説明](../images/<scene-id>.png)`. Only `../images/*.png` is
  used for pictures, so the pages read the same in an editor, on GitHub and wherever the manual is
  hosted. `client/tests/manual-pages.test.ts` fails when a page refers to a picture that is not
  there.
- Every picture in `images/` comes from a scene in `client/tests/manual/scenes.ts`. Do not edit
  the PNGs by hand: the next shoot overwrites them.

## Taking the screenshots again

```bash
pnpm manual:shoot                       # every scene (builds the preview pages first, ~1 min)
pnpm manual:shoot -g approval-card      # one scene, by id
```

Run it after a change to the screens (a redesign, new wording) and commit the changed PNGs with
it. Shoot on a Mac: fonts differ between systems, and the manual shows the Mac app. The shots are
deterministic on one machine (fixed clock 2026-11-20 10:30 Asia/Tokyo, 1280×800 at 2x, light
theme, no animations): a second run without changes rewrites the same bytes, so `git status`
shows only the pictures that really changed.

A shoot fails, rather than saving a wrong picture, when a step or an annotation cannot find its
target (exactly one visible element) or the page throws.

## Adding a scene

A scene is data in `client/tests/manual/scenes.ts`:

- `page` (+ `query`): which preview page to open (`client/tests/<page>-ui.html`, the real React
  components with the app's background parts faked; the same pages the UI tests use).
- `steps`: clicks, right clicks, double clicks, hovers, typing (`fill`, `typeAtEnd`), keys, a preview page's own hook
  (`run`) and waits to reach the state to show.
- `crop`: an element (with padding) or a region to cut out; the whole window when absent.
- `annotations`: red frames (`box`), numbered red markers (`marker`, placed top-left, left,
  right or below the target) and red-framed labels under icon-only buttons (`note`, the name
  their tooltip shows). The text of the page refers to the numbers.

Pictures have no caption under them: the page's text says what each number is, and the alt text
describes the picture.

The main screen and the screens before a company opens show the manual's own company with
`manual: '1'` (`skill-layout-ui.html`, `company-selector-ui.html`): 検証A社, 山田 太郎 in 営業部,
総務部 not downloaded, one consultation in 「AIへの相談」.

### Names of buttons

The text writes the name of a button or label the member presses or reads as ［名前］ (full-width
brackets), exactly as the screen shows it (a count as the screen shows it too:
［選んだ部署をダウンロード（1）］). `client/tests/manual-ui-names.test.ts` (client tests, in CI)
checks that every such name is still one whole piece of text in the app's screens (`client/src`,
the words they take from `client/shared` (`thing-words.ts`…), sync's questions in the Mac's own dialogs `client/electron/sync/`, the admin console's invitation
page `admin/src/app/invite/`), so the pull request that renames a
control fails until the manual says the new name. Use ［…］ only for names on screens; quote
other words with 「…」. A name on a screen this repository does not draw goes in
`ui-names-allowlist.json` as `"名前": "why it is not in the app's source"` (the test refuses an
entry without a reason, and one no page cites any more).

### Diagrams

A diagram (`diagram: true`) is static HTML in `client/tests/manual/diagrams/<id>.html`, drawn on
the design tokens' colours (the shoot puts `primitives.css` and `theme.css` in front of it) and
shot to `images/<id>.png` like a screen. The site takes pictures only as PNG/JPEG/WebP (no SVG,
which could carry a script: `shared/core/manual.ts`), so diagrams become PNG here rather than the
site accepting another format. Plain words only (no Git terms), Japanese labels.

Targets are Playwright selectors, preferably by role and visible name
(`role=button[name="サーバーと同期"]`), so they keep working when the look changes.

Everything shown must be fictional (検証A社, 山田さん, 佐藤さん): no real people, companies or
private-folder names. When a preview page lacks the state you need, add it to that page behind a
query parameter (and keep its UI spec passing) rather than changing app code for the manual.
