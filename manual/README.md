# User manual (取説)

The manual for members, with screenshots taken automatically from the real app screens.

```
manual/
  pages/<name>.md        the manual's text (Markdown, Japanese, written for non-engineers)
  images/<scene-id>.png  screenshots, generated by `pnpm manual:shoot` and committed
```

- A page refers to a picture as `![説明](../images/<scene-id>.png)`. Only `../images/*.png` is
  used for pictures, so the pages read the same in an editor, on GitHub and wherever the manual is
  hosted. `client/tests/manual-pages.test.ts` fails when a page refers to a picture that is not
  there.
- Every picture in `images/` comes from a scene in `client/tests/manual/scenes.ts`. Do not edit
  the PNGs by hand: the next shoot overwrites them.

## Taking the screenshots again

```bash
pnpm manual:shoot                       # every scene (builds the preview pages first, ~1 min)
pnpm manual:shoot -g approval-card      # one scene, by id
```

Run it after a change to the screens (a redesign, new wording) and commit the changed PNGs with
it. Shoot on a Mac: fonts differ between systems, and the manual shows the Mac app. The shots are
deterministic on one machine (fixed clock 2026-11-20 10:30 Asia/Tokyo, 1280×800 at 2x, light
theme, no animations): a second run without changes rewrites the same bytes, so `git status`
shows only the pictures that really changed.

A shoot fails, rather than saving a wrong picture, when a step or an annotation cannot find its
target (exactly one visible element) or the page throws.

## Adding a scene

A scene is data in `client/tests/manual/scenes.ts`:

- `page` (+ `query`): which preview page to open (`client/tests/<page>-ui.html`, the real React
  components with the app's background parts faked; the same pages the UI tests use).
- `steps`: clicks and waits to reach the state to show.
- `crop`: an element (with padding) or a region to cut out; the whole window when absent.
- `annotations`: red frames (`box`) and numbered red markers (`marker`, placed top-left, left,
  right or below the target). The text of the page refers to the numbers.

Targets are Playwright selectors, preferably by role and visible name
(`role=button[name="サーバーと同期"]`), so they keep working when the look changes.

Everything shown must be fictional (株式会社デモ, 検証A社, 山田さん): no real people, companies or
private-folder names. When a preview page lacks the state you need, add it to that page behind a
query parameter (and keep its UI spec passing) rather than changing app code for the manual.
