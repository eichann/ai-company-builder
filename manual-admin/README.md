# Administrator / FDE guide (管理者・FDE の手引き)

The guide for the people who set a company up and run it: owners, admins and the FDE (the
engineer who helps a company start and automate its work). The member manual is `manual/`; this
is its counterpart for the admin console (`admin/`).

```
manual-admin/
  pages/<name>.md        the guide's text (Markdown, Japanese; index.md is the 序章)
  images/<id>.png        screenshots and diagrams, generated by `pnpm manual-admin:shoot` and committed
  ui-names-allowlist.json  ［names］ the guide cites that the source does not hold whole, each with its reason
```

Status:

- **Served** at `/manual-admin/` by the server, to accounts that are an owner or admin of at least
  one company (`.claude/rules/server.md` "The administrator guide"); the admin console's menu has
  「管理者の手引き」 for them. Built into the server image by the members' manual's build
  (`server/src/cli/build-manual.ts manual-admin …`): a link to a missing page or a picture that is
  not there stops the image build. By hand: `pnpm --filter @ai-company-builder/server manual-admin:build`.
- A page refers to a picture as `![説明](../images/<id>.png)` (PNG only: the site takes pictures
  as PNG/JPEG/WebP, never SVG, `shared/core/manual.ts`). `admin/tests/admin-guide-pages.test.ts`
  (admin tests, in CI) fails when a page shows a picture that is not there, and when a ［name］ the
  guide cites is no longer one whole piece of text in the admin console (`admin/src`) or the app
  (`client/src`, `client/shared`) — or is listed in `ui-names-allowlist.json` with its reason.
  Do not edit the PNGs by hand: the next shoot overwrites them.

## Taking the screenshots again

```bash
pnpm manual-admin:shoot                     # every admin console scene (builds the admin first, ~1 min)
pnpm manual-admin:shoot -g members-list     # one scene, by id
pnpm manual:shoot -g admin-app              # the app's screens the guide shows (10・13・15節)
```

Not run in CI. Shoot on a Mac (fonts differ between systems) and commit the changed PNGs; a
second run without changes rewrites the same bytes. Fixed: the clock 2026-11-20 10:30
Asia/Tokyo, 1280×800 (a scene may set its own size) at 2x, Japanese, light theme, no animations.

How it works (`admin/tests/manual/`):

- **The real admin console**: the shoot builds it (`next build`) and runs `next start` on
  127.0.0.1:3110 (`playwright.config.ts`; `MANUAL_ADMIN_REUSE=1` uses one you started there — stop
  it when done). No admin code knows about the shoot.
- **A fictional company instead of a server**: every `/api/*` request the page makes is answered
  in the browser (`page.route`) from a table: `world.ts` (検証A社, its people, departments and
  what every company page loads, signed in as 高橋さん, the owner), `answers.ts` (each page's reads
  in a calm, set-up state, and the states the chapters show) and the scene's own `api`. The
  answers are typed by the console's own API types (`tsc` keeps them in shape) and its run-time
  schemas check them again. `API_PROXY_URL` points at a closed port, so nothing can reach a real
  server. **A shot fails** — no picture is saved — when the page makes a request the table does
  not answer, throws, or shows 「読み込めませんでした」 (an answer of the wrong shape).
- **Scenes as data** (`scenes.ts`): `path` (a page of the console, `at('/members')`), `steps`
  (click, hover, fill, select, press, run, waitFor), `crop` (an element, or from one element down
  to another with `to`, plus padding), `annotations` (red frames, numbered markers, labels), as in
  the members' manual (`manual/README.md`). Targets are Playwright selectors, preferably by role
  and visible name; each must match exactly one visible element. The guide's text says what each
  number is; pictures carry no caption.
- **Diagrams**: `diagram: true` with `admin/tests/manual/diagrams/<id>.html` (static HTML on the
  design tokens), shot to PNG like a screen.
- **The app's screens** (a member's settings, the plan card): scenes with `guide: 'admin'` in
  `client/tests/manual/scenes.ts`, shot from the members' manual's preview pages into this folder.

Everything shown is fictional (検証A社, 高橋さん, 佐藤さん, 田中さん, 山田さん, 小林さん, 中村さん,
伊藤さん; `*.example` addresses): no real people, companies, keys or private-folder names, never
production data. A state a chapter needs is added to `answers.ts` (or the scene's `api`), never to
the admin console.

Writing rules (same as `manual/`):

- Japanese for non-engineers; Git words only in sections marked 【FDE】, explained once.
- Button and label names as the screen shows them, in ［…］; other words in 「…」.
- Page names are ASCII `a-z`, `0-9` and `-`, numbered in reading order.
- Everything shown is fictional (検証A社, 高橋さん, 佐藤さん, 山田さん, 田中さん, 小林さん, 中村さん, 伊藤さん).
- Describe only what the code does today. Something being built gets at most one line saying so.
