# 相談チャットのCodex対応

更新日: 2026-10-20
ブランチ: refactor/agent-connection

## 今回の範囲

相談設定に「Codex（ChatGPTプラン）」を追加する。既存のClaude Code／Anthropic APIキー方式を維持する。長期引き継ぎは対象外。音声整形の接続先切り替えを追加し、詳細・実測結果は `voice-provider-formatting.md` を参照。

各PCのCodex CLIをstdioで子プロセスとして起動し、公式app-serverのJSON-RPCを利用する。ChatGPTログインを確認し、APIキー認証にはフォールバックしない。未インストール・未ログインの場合は設定画面で手順を表示する。認証情報をACBの設定や履歴へコピーしない。

## 接続層

- agents/codex-rpc.ts: 実行ファイル探索、JSON-RPC相関ID、30秒の制御リクエスト上限、接続終了時の待機解除。
- agents/codex.ts: 認証、モデル一覧、スレッド開始／再開、ターン実行／停止、承認、イベントからVercel LanguageModelへの変換。
- agents/process.ts: ElectronのFD対策とWindows起動をClaude／Codexで共有。
- agents/session.ts: プロバイダー・モデルの一致判定と、持ち運べる入力の選択。

プロセスは実行ごとに起動し、完了・失敗・キャンセル時に閉じる。停止はturn/interruptを送信し、終了しないプロセスは2秒後に終了させる。回答の実行上限は15分、タイトルは90秒。自動リトライでツール操作が二重に実行されないよう、相談リクエストの再試行は行わない。

## モデルとeffort

Codexのmodel/listから取得する。Claudeのモデル名・effortをCodexへ渡さない。選択値はプロバイダー別に保持し、モデル変更により非対応になったeffortはそのモデルの既定値にする。実行側でも最新の一覧に対して検証し、不正な選択値はエラーにする。

回答中はモデル選択を無効化する。接続方式の設定を変更しても、進行中のリクエストには送信時点の方式を使う。タイトル生成はCodexでは選択中のモデルのlow（非対応なら既定effort）で独立した一時セッションを使う。Claudeのタイトル生成は従来のHaiku。

## 同じ相談で切り替える

ACBの相談ID／画面の履歴と、AIの内部セッションを分離する。履歴JSONへ `agentSession: { providerId, id, modelId? }` を追加する。旧 `claudeSessionId` は移行用に読む。

- 同じプロバイダー・モデル: 同じ内部セッションを再開し、最新のユーザー入力だけを送る。
- プロバイダーまたはモデルが変わった: 表示履歴から新しい内部セッションを開始する。
- 元のプロバイダーへ戻った: 古いセッションには戻らず、更新された表示履歴から新しく開始する。
- APIモードを経由した場合も切り替えとして扱う。

これにより、別AIとの相談内容が抜けた古いセッションを誤って再開しない。文章と画像を移すが、思考・ツール呼び出し・ネイティブ実行状態は移さない。履歴の文章が160,000文字を超える場合はエラーを示し、黙って履歴を切り捨てない。文字数上限はトークン上限の保証ではない。

内部セッションIDは完了結果から受け取り、履歴のメタデータ更新で保存する。古い画面の自動保存が、新しい接続先のIDを上書きしないようにする。既存履歴を一括移行する必要はない。

## 操作承認と未対応の要求

Codexはread-only sandboxとuntrusted承認方式を使う。コマンド／ファイル変更の承認要求は、相談IDを付けて既存の承認UIへ渡す。承認者はuserを明示する。Claudeの「自動」設定をCodexの無条件実行には読み替えない。

選択式質問と追加権限要求は相談内の確認カードへ渡す。質問は最大3問、選択肢／許可された自由記入／秘匿入力に対応し、質問IDごとに回答を返す。空回答は送らず、「回答せず停止」でターンを中断する。

追加権限は理由・作業フォルダ・読み取り／書き込み対象・ネットワーク接続の有無を表示。「今回だけ許可」は元の要求の範囲をそのままscope=turnで返し、次の応答以降へ持ち越さない。任意の範囲をrendererから指定することはできない。未知の権限フィールド、glob、特殊パス等、完全に表示・確認できない形式は許可ボタンを無効化し、拒否のみ可能にする。MCP elicitationは引き続き別途対応で、現在は拒否する。

確認要求はメインプロセスで一意ID・renderer所有者・相談IDを付けて管理する。別rendererの回答、期限切れ・重複回答、不正な回答を拒否する。5分未回答時は質問を停止／権限を拒否。サーバーによる確認の取り消し（serverRequest/resolved）・完了・中断・ウィンドウ終了・ページ遷移・タブを閉じた際にも待機を解消し、カードを消す。単なる相談の切り替えでは保持し、戻って回答できる。回答内容をACBの履歴JSONやログへ保存しない。

2026-10-20検証: 自動テスト52件通過（元の音声・履歴テスト含む）。型チェック・ビルドと既存警告を除くLint成功。実コンポーネントのプレビューで選択／自由記入／許可／拒否を確認。Codexプロトコルの疑似要求で返答形式、権限範囲、scope=turn、キャンセル時の遅延返答防止を確認。実際のモデルにこの2種類の要求を発生させての通し確認は未実施。利用者による実アプリ試用待ち。

## 検証

- 接続・履歴を含む自動テスト36件通過。型チェック・ビルド成功、Lintは既存の警告3件のみ。切り替え時の再開防止、モデル／effort検証、ChatGPT認証、承認拒否、停止、タイトル分離、古い自動保存の耐性。
- このMacのChatGPTログインを利用した実応答。
- 実際のHTTPストリームで回答を受け、サーバー再起動後に保存済みIDで合言葉を再現できることを確認。
- 実際のChatPanelを使った確認用画面でClaude→Codex→Claude、モデル／effortの候補変更を確認。
- 実際のファイル読み取りで、承認拒否時は実行されず、承認時は読み取った内容とツール結果がチャットストリームに返ることを確認。
- Windows版ACBでのCodex相談は現在未対応として設定・実行時に案内し、起動を止める。

今回の方式はローカルアプリでの利用を前提とする。商用／ホスト型サービスへの展開時には公式Sign in with ChatGPTの適用条件を別途確認する。

## 後続候補：画像生成

Codexの組み込み画像生成はChatGPTの利用枠に対応する。ACBでは生成イベントの扱い、プレビュー、指定先への保存を今後追加する。今回の接続だけで任意フォルダへの生成・保存が検証済みとは扱わない。書き込み可能な保存先を指定し、既存ファイルの上書きは別途扱う。

## セッション一覧の共有について

現在は既存Codexの認証と保存領域を使い、相談を永続スレッドとして作成するため、Codex/ChatGPTアプリ側の一覧にもACBの相談が表示される場合がある。音声整形とタイトル生成はephemeralで、相談のように永続化しない。利用者は2026-10-20に、分離が難しい場合は現状を許容すると回答。再ログイン・履歴継続のリスクを伴う保存先分離は今回導入しない。長期引き継ぎメモは後続対応。
