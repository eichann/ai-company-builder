# 相談間参照の実装・検証

2026-10-20 / `feat/consultation-reference` / 未マージ

## できること

- 同じ会社の、利用者PCに保存された相談のタイトル・引き継ぎメモを必要時だけ検索する。
- 関連する相談のメモと、必要な原文を読み、現在の回答に使う。
- Claude/Codex双方の既存セッションへ接続する。相談の作り直しは不要。
- 「参照した相談」から元の相談を開く。参照元の識別情報は履歴にも保存し、再読込時に復元する。
- 閉じた相談も対象。削除後は読み取り時に拒否し、他の会社・現在の相談は対象外。

## 接続方法

共通処理は `electron/consultations/service.ts`。ClaudeはインプロセスMCP、Codexは回答中だけ起動する認証付きループバックHTTP MCP。Codexのthread/resumeへMCP設定を渡し、既存セッションに参照ツールがなかった場合も利用できることを実機で確認した。接続情報をユーザーの設定ファイルには保存しない。

依存追加は公式の`@modelcontextprotocol/sdk`。独自のMCPプロトコル実装はしない。検索・読み取りに別のAI処理や常駐プロセスを設けない。

## 実認証での検証

人工データのみを使用し、既存の利用者の相談を削除・書換えしていない。

各AIについて、参照ツールなしで新規セッションを作成 → 同じIDをresumeして検索・読み取り → もう一度resumeして検索・読み取り、を実行した。

| 検証 | Claude | Codex |
|---|---|---|
| 検索＋原文読取 | 約8.7秒、7.3秒 | 約17.0秒、11.8秒 |
| 検索＋メモ＋原文で訂正を確認 | 約8.4秒、6.5秒 | 約26.3秒、20.7秒 |
| 古いメモ15,000円 → 原文の訂正12,347円 | 正しい訂正後の金額を回答 | 正しい訂正後の金額を回答 |
| 実際のツール結果から参照リンクを抽出 | 成功 | 成功 |

時間はモデル応答を含む1回の依頼全体。少数試行であり、速度保証や純粋な機能追加による遅延ではない。モデル・混雑・標準スキル設定によって変わる。Codexログには標準tool_searchの未対応要求が出る場合もあったが、今回の参照MCPは成功した。

## 消費量の扱い

検索結果は最大5件・約2 KiB、読み取り本文は1回8 KiB、1ユーザー発言につき合計4回・メタデータ込み20 KiBまで。予算は再接続・復旧によって増やさない。検索対象全件をAIへ送らず、要約の再生成も行わない。

ただし2〜3回のツール利用はモデルの処理回数を増やす。この環境では通常のシステム指示・スキル等だけでも約2万トークン以上の入力があり、Claudeの参照依頼では複数ステップ合計のキャッシュ読取が大きい。Codex接続が返すusageは最後のステップ中心であり、両者の数字を直接比較したり、検索結果のバイト数だけで契約枠の消費が少ないと断定したりしない。初期版の制御対象は呼び出し回数と追加資料の量で、厳密な課金上限ではない。

訂正を確認した試行でAIへ返した検索・読み取り結果は、両AIとも合計1,565バイトだった。Claudeの報告値は合計入力約64,000〜108,000トークン（大半がキャッシュ読取）。Codexの最後のステップは約25,000〜28,000トークンで、これを依頼全体の総量とは扱わない。

実測の生データは今回の一時検証先 `/tmp/acb-reference-probe-1`、`/tmp/acb-reference-probe-2` にある。再実行用スクリプトは `client/scripts/consultations/probe.ts`。

## ローカル検索の負荷

1相談あたり約24 KiBの原文と短いメモを持つ人工データで測定。

| 件数 | 履歴JSON | 検索時間 | 処理前後のヒープ差分 | AIへの結果 |
|---|---|---|---|---|
| 100 | 約2.4 MB | 約51 ms | 約6 MiB | 約1.4 KiB |
| 1,000 | 約24 MB | 約377 ms | 約43 MiB | 約1.4 KiB |

ヒープ差分はピーク値ではなく、GCの影響もある。会社全体のJSONを読む既存の構造は維持しており、履歴が増えてもメモリが一定とはならない。候補ごとの履歴再読込と、全原文の永続キャッシュは避けている。再実行用は `client/scripts/consultations/benchmark.ts`。

## 自動検証と画面確認

既存を含む79テスト、TypeScript型検査、Viteビルドを確認。専用テストでは所属・削除・予算・入力検証・中止・メモの後の訂正・原文分割・MCP認証・参照リンク解析を検証した。追加コードのLintも成功。

表示用の人工データ画面で参照リンクとクリックを確認。本番の相談タブへ遷移する操作は、利用者のACB上での最終確認対象とする。

## ACBでの確認手順

1. 過去の相談のタイトルに含まれる言葉で「前に別の相談で話した○○を探して、決定事項を教えて」と依頼する。
2. 回答中の「参照した相談」を開き、該当する相談に移れることを確認する。
3. ClaudeとCodexをそれぞれ選び、同じ参照先を使えることを確認する。

メモがまだない相談はタイトルから検索し、原文を読める。タイトルにもメモにもない語は初期版では見つからない場合がある。相談の原文全体の横断検索や意味検索は未実装。APIキーモードは今回の対象外。
