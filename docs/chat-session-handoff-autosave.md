# 引き継ぎメモ：自動保存の確認段階

2026-10-20 / ブランチ `feat/chat-session-handoff`

## 今回の仕様

アーカイブ機能は追加しない。相談のタブを閉じる・切り替える・アプリを再起動する操作で履歴とメモは消さない。既存の相談削除操作だけが、履歴とメモ本文・バックアップ・一時ファイルを削除する。削除記録の永続化を先に行い、生成中の中止、遅延保存の拒否、起動時の削除完了にも対応する。期限による自動削除はない。

正常終了した応答を履歴に保存した後、その応答IDと本文を照合して更新対象を確定する。中止・通信切断・エラー終了は対象外。新規16往復または約12,000文字で更新予約し、通常のAI応答が動いていない状態から20秒待つ。通常チャットが始まれば要約処理を中止して後回しにする。失敗時は旧メモを保持し、無制限の再試行はしない。

同じ相談は10分間隔、全体は1時間4回まで。同時生成は1件。失敗・中止も利用量に数え、再起動後も制限を維持する。手動の「メモを更新」もこの制限を適用する。

前のメモと連続した未処理の会話だけを渡す。入力は32KiB・14,000文字以内、メモは8KiB以内。大きい会話は区間を区切り、次回に続きを処理する。履歴の全件コピーを別途維持しない。思考内容・画像データは要約に含めない。

ClaudeはAgent SDKのプロセス内ツール、Codexはapp-serverのdynamicToolsを使う。共通の `save_handoff` の結果を検証し、AI処理が正常終了してから正式保存する。元のプロジェクトとは別の作業場所で実行する。APIキー方式は今回未対応。

## ACBでの確認方法

1. Claude CodeまたはCodexの相談で、1回応答を完了させる。以前の相談も、まず新しい正常終了の応答が必要。
2. チャット上部の「引き継ぎメモ」を押し、「メモを更新」を押す。通常は約20秒待ってから生成する。利用量制限中は待機する。
3. 保存時刻・内容を確認する。相談を閉じ、履歴から開き直しても残る。
4. 削除の確認には不要なテスト相談を使う。削除後はメモとバックアップも消える。

自動保存の閾値に達した相談では、手動操作は不要。

## 検証

- 自動テスト65件成功。保存との照合、重複通知、削除中の生成、再起動、メモ保持、履歴変更、同時会話の優先、利用量制限、巨大な文章の分割を含む。
- TypeScript検査、Vite本番ビルド成功。新規メモ関連ファイルのlint成功。
- 実際のClaude/Codex認証と本番用サービス・ストアを用いた人工会話で、更新予約から生成・保存・再読み込み・削除を検証。検証時のみ待ち時間50ms、2回の完了通知で起動する設定。

| AI | 生成時間 | 入力トークン | 出力トークン |
|---|---:|---:|---:|
| Claude | 15.5秒 | 9,315 | 3,212 |
| Codex | 13.5秒 | 11,443 | 1,088 |

各1回の結果で速度保証ではない。SDKの指示なども含む使用量。通常の毎応答に上乗せする処理ではない。

両方とも変更後の予算・納期・担当、JSON維持の理由、公開前のユーザー確認、AI報告と検証済み事実の区別を保持した。Codexは決定済みの取消方針について、追加の「案の具体化」を未解決事項に残した。要約の品質は完全ではなく、実際の相談でも内容を確認する。

実コンポーネントを使う人工データの画面でダイアログの表示を確認。ACB開発版の本体でも確認ボタンの表示を確認した。本体画面を通した生成操作の最終確認はユーザー確認段階。

## 次の段階

今回はメモの自動保存まで。ネイティブセッションが失われた時の自動検出・メモと直近会話を使った新規セッションへの復旧は未接続。これを接続して初めて、長期のセッション喪失後も自然に相談を継続できる。
