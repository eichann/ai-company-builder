# 引き継ぎメモ: 段階Aの検証結果

実施日: 2026-10-20 / ブランチ: `feat/chat-session-handoff`
基点: main `4b205b2`。以下は段階A時点の記録。現在は段階B/Cを接続済み・未マージ。最新の検証は `chat-session-handoff-recovery.md` を参照。

## 結論

Claude・Codexの両方で、専用ツール経由のメモ保存、差分更新、メモと未整理の会話だけを使った新規セッションでの継続を確認した。元のネイティブセッションが使えなくても相談を続ける構成は成立する。

ただし、この小さな検証で長期間・大量の会話の品質まで保証したわけではない。AI報告の確かさ、判断理由、承認者を維持するための調整が必要。今回の段階で確認してもらう対象は生成例と測定結果であり、ACB画面に自動復旧が完成したという意味ではない。

## 元の問題: 約1か月後のセッション消失

[Claude公式資料](https://code.claude.com/docs/en/claude-directory#cleaned-up-automatically)では、セッション記録は`cleanupPeriodDays`による削除対象で、既定は30日。保存設定・バージョンに依存するため「必ず作成から30日で消える」とは断定しない。利用者の保存設定は変更していない。

今回の再開検証では次の条件を作った。

1. メモ生成はClaudeでは`persistSession: false`、Codexでは`ephemeral: true`で実行。
2. 生成用の接続を終了し、ホスト側のメモストアも新しいインスタンスで読み直した。
3. 元のセッションIDも、要約済みの元会話も渡さず、保存されたメモと追加発言だけを新規実行に渡した。
4. 訂正後の担当・予算・期限、未提出のテストログ、新しく追加した画面確認会を答えられた。
5. 生成時のIDを別途resumeして、Claudeは`No conversation found with session ID`、Codexは`no rollout found for thread id`で再開不能になることを確認した。

実際のユーザーのセッションは削除していない。30日間の時間経過や、実際の清掃処理そのものは再現していない。「ネイティブセッションがない状態からの情報の引き継ぎ」を実証した。再開不能の検知からACBのセッションID更新までの自動処理は段階Cで実装・検証する。

ACBの保存先をClaude/Codexの保存領域と分け、日数では削除しないことが重要。メモ作成条件に達していない短い相談も、残っている履歴から再開する経路を設ける。

Codex出力のうちreasoningは初回51、差分70トークン。Claudeの表の出力から可視テキストと内部推論は分離していない。両社の集計方法やキャッシュは同一ではなく、数値をそのまま請求額に換算しない。

Claudeは2ターン（専用ツール呼び出しと終了応答）。Codexも保存ツールを1回呼び、終了した。生成モデルに見える固定の指示やツール定義、保存後の応答まで含むため、短いメモでも数千トークンを消費する。毎回の会話終了ごとに生成する案は採用しない。

差分方式でも前回メモを再入力する。今回のClaudeの差分は前回メモが長く、初回より消費が増えた。「差分なら常に安い」とは言えない。段階Bの頻度上限に加え、メモの簡潔さを調整する必要がある。サブスクリプションの利用枠の減り方や追加料金は測定していない。

初回試験ではClaudeがAIの報告を「確認済み」に強め、実行環境の作業パスをメモに混ぜた。Codexは差分更新時に決定の理由を落とした。入力外の情報を追加しないこと、変更されていない理由と制約を維持すること、AI報告を未検証と記すことをpromptに追加して改善した。

修正後にも残る課題:

- Claudeは、元の会話に明示されていない引き継ぎ時期・範囲などを未解決事項として補い、次の手順も増やした。大筋は合っているが、忠実なメモとしては冗長。
- Codexのメモに日本語以外の単語が1か所混入した（「3つ בלבד」）。内容上は3項目の限定だが、表記品質の課題。
- Codexの再開回答では、画面確認会の参加者である田中さんと、公開前に確認するユーザーの役割が曖昧になった。メモにはユーザー確認が残っているが、再開時の読み取りにも改善の余地がある。

したがって、基本的な継続性は確認できた一方、完全な記憶や誤解のない自動引き継ぎは保証しない。メモを承認権限の根拠にはしない。段階Bで文章の短さと忠実さを調整し、段階Cで承認者を含む復旧動作を再確認する。

## 削除

検証用ストアで次を確認した。

- メモ本文、1世代前のバックアップ、一時ファイルを削除。
- 実行中の生成を中止するシグナルを発行。
- 遅れて到着した保存要求を拒否。
- ストア再作成後も削除状態を維持し、メモを再生成・復元しない。
- 削除記録を書いた後に終了した場合でも、次回起動時に残るバックアップを削除。

残るのは本文を含まない削除記録だけ。この節は段階Aの検証記録。段階Bでは既存の相談削除UIに接続する。タブを閉じるだけでメモを削除する仕様にはしていない。人工データの検証レポート・見本は評価用の独立成果物として残しており、本番で見本の二重保存は行わない。

## 次の段階

まずこの生成例と消費量を確認してもらう。その後、メモの品質調整を続けながら、正常終了と履歴保存の結合、範囲照合、自動更新の条件、削除状態、表示へ接続する。最後に再開不能の判定・新セッションの作成・ID保存をつなぎ、ACB画面での長期継続を確認する。

段階Aの試験用ストアは本番用の会社・相談・履歴ハッシュ照合をまだ持たないため、そのまま本番へ接続しない。Codex dynamic toolsはexperimentalであり、非対応CLIの場合は自動保存だけを停止できるようにする。

## 再実行

リポジトリで依存をインストールした後、以下を実行する。出力先は存在しない絶対パスを指定する。人工会話のみだが、AIのサブスクリプション利用枠は消費する。

```sh
pnpm --filter @ai-company-builder/client handoff:probe claude-code /absolute/new/claude-trial
pnpm --filter @ai-company-builder/client handoff:probe codex /absolute/new/codex-trial
pnpm --filter @ai-company-builder/client handoff:probe-absence claude-code /absolute/new/claude-trial
pnpm --filter @ai-company-builder/client handoff:probe-absence codex /absolute/new/codex-trial
pnpm --filter @ai-company-builder/client test:handoff
```

Claude CLIは既定で`~/.local/bin/claude`。別の場所なら`ACB_HANDOFF_CLAUDE_CLI`で指定する。実行結果には各メモ、再開回答、使用量、削除検証を保存する。
