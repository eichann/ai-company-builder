# 同じ相談のセッション不在からの復旧

2026-10-20 / `feat/chat-session-handoff` / 段階C

## 実装した動作

通常は従来どおり既存のAIセッションを使い、最新の入力だけを送る。毎回メモを送ったり、存在確認のために別のAIを呼んだりしない。

Claude/Codexの接続層が、再開対象のIDについてセッション不在を明確に確認した場合だけ、新規セッションに1回切り替える。メモとメモ作成後の会話、今回の依頼を渡す。メモを生成し直すための追加AI呼び出しは行わない。

- Claude: 指定IDに対する `No conversation found with session ID: ...` を検出。利用中のSDKがエラーのstderrを失う場合があるため、その呼び出し専用の子プロセスでも該当行だけを検出する。
- Codex: `thread/resume` への `no rollout found for thread id ...` を接続層で専用エラーに変換する。他のRPCの失敗では切り替えない。
- 通信・認証・権限のエラーや、すでに応答/ツール活動が始まった後の失敗は、自動で再実行しない。
- 新しいセッションの開始通知で新IDをローカル履歴へ保存する。応答の完了を待たず保存するため、途中で停止した場合も次の送信で古いIDへ戻らない。
- 中止するとネイティブエージェントの処理も中止する。
- 画面に「文脈を引き継いで再接続中…」「メモと会話から再接続しました」を表示する。通常の会話履歴にシステムの説明文は追加しない。

## 引き継ぎ量と境界

メモの元になった履歴範囲とハッシュを照合し、現在の送信履歴とも照合する。メモ以降の文章は順番を保って渡す。分割保存中のメモなら、文章の途中から残りを引き継ぐ。要約済み部分の全履歴は再送しない。

メモと未整理の会話はUTF-8で32KiB以内。超える場合は黙って途中を落とさず、メモを更新して再送するよう案内する。現在の依頼・添付画像は通常の送信経路で渡す。過去の画像、思考内容、ツールの内部状態は復元しない。メモは参考情報として渡し、操作の承認や新しい指示にはしない。

メモがなくても短い会話なら保存した会話から継続する。古い相談で正常終了の記録がまだない場合も、既存のClaude/Codex接続情報があれば「メモを更新」で履歴から作成できる。自動更新の頻度・利用量上限は維持する。

タブを閉じる操作ではメモを消さない。相談を削除したときだけ、メモとバックアップを削除する。別の相談の検索は未実装。AI/モデルの切り替えは従来の表示履歴による引き継ぎのまま。

## 検証結果

ACB本体と同じHTTPチャットサーバー、接続層、ストアを使用し、実際のサブスクリプション認証で確認した。利用者のネイティブセッションは削除せず、人工会話に存在しないランダムIDを設定して不在を再現した。

| 項目 | Claude | Codex |
|---|---|---|
| 不在検出→メモを使った回答完了 | 約7.9秒 | 約8.5秒 |
| メモの15万円→後続会話の12万円に訂正 | 成功 | 成功 |
| 担当・納期・JSON維持の理由・ユーザー確認条件 | 保持 | 保持 |
| 新IDを履歴へ保存 | 成功 | 成功 |
| 次の入力で新IDを再利用 | 成功 | 成功 |
| サーバーと履歴ストアの再作成後に継続 | 成功 | 成功 |

各1回の小規模測定。30日間の実時間経過や、大量の相談での要約品質を保証するものではない。2000年の日付を付けたメモでも日数による削除はないことを含めて検証した。Claudeはテスト未実施の記載から公開前のテストを条件として補足する回答もあり、生成文の厳密さは実相談での確認が必要。

自動テストは既存72件と追加2件、計74件成功。エラーの種類による再実行制限、二重実行の防止、中止の伝播、メモ範囲の照合、分割された文章、古い相談からの手動生成を含む。型検査・Viteビルド・変更した接続層とメモ関連ファイルのlintを確認。

再接続通知の画面は実コンポーネント＋人工データで表示確認した。実際のACB操作による長い相談の確認は次のユーザー確認段階。

## ACBで試す

1. 開発版で会社と相談を開く。
2. 上部の「引き継ぎメモ」を開き、保存内容を確認する。未作成なら「メモを更新」を押す。開始待ち時間と利用量制限は適用される。
3. 以前使っていて、AI側のセッションがなくなった相談に通常どおり送信する。
4. 自動で引き継ぎが行われた場合、再接続通知と回答を確認する。
5. もう一度送信する。さらにアプリを再起動して同じ相談から継続する。

有効なセッションでは復旧表示が出ないのが正常。確認のために実データやCLIセッションを削除する必要はない。人工会話での再現検証は `client/scripts/handoff/recovery-probe.ts` に残した。
