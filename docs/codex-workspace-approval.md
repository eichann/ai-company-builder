# Codexの通常相談の許可設定

2026-10-20 / `fix/codex-workspace-approval`

## 変更

ACBのCodex通常相談は、新規開始・既存セッション再開の両方で以下を毎回指定する。設定画面での切り替えは不要。

- `sandbox: workspace-write`
- `approvalPolicy: on-request`
- `approvalsReviewer: user`

対象フォルダはACBが渡す会社の作業ディレクトリ。通常の編集・実行はその範囲内で進み、境界を超える追加権限は既存の確認UIへ送る。許可を一律に自動承認したり、ユーザーのCodexグローバル設定を書き換えたりしない。

作業フォルダが指定されない例外経路では共有一時ディレクトリへの書き込み権限を与えず、read-onlyへ制限する。タイトル生成、音声整形、引き継ぎメモ生成などの専用補助処理は、従来の限定した権限を維持する。

設定画面に「作業フォルダ内の通常作業は自動で進めます。フォルダ外への書き込みや、追加権限が必要な操作では確認します。」と表示する。

## 検証

- Codex接続の11テスト成功。新規・再開への設定適用、フォルダ未指定時の制限、タイトル生成のread-only維持、許可の拒否・キャンセルを含む。
- ワークスペースの型検査とViteビルド成功。
- 実認証の人工データ検証は `client/scripts/codex/approval-probe.ts`。新規・再開した相談で作業フォルダ内のファイル作成、フォルダ外への書き込み要求の拒否を確認済み。新規・再開の内部保存は確認0回、外部保存はBash許可確認1回で拒否し、ファイルは生成されなかった。
- 許可拒否でCodexがturnをinterruptedとして終える場合もあるため、検証では拒否要求が実際に到着し、外側のファイルが作られなかったことを判定する。

## 制限

workspace-writeはCodexのサンドボックス境界に従う。OS・CLI設定で認められた一時ディレクトリ等の例外もあり、「作業フォルダ外のすべての操作で必ず確認」とは同一ではない。ネットワーク等の追加権限やMCP側の確認は引き続き発生し得る。既存の確認UIと拒否経路は維持する。
